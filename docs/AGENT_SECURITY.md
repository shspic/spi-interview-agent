# Agent 安全边界

## 不受信内容

用户回答、上传文档、简历、JD、检索片段和面试历史都属于不受信数据。Evaluation 和 Resume Prompt 使用明确边界传递这些数据，并声明其中的角色切换、评分操纵、提示词泄露、跨用户访问、来源绕过和简历事实伪造要求不得执行。

共享守卫在发送模型前进行 Unicode 规范化、空白与分隔符归一化和组合语义检测。检测结果按风险类型记录，危险行替换为固定占位符；日志不包含原文。正常的权限系统、Prompt 模板和 Prompt Injection 防护技术描述保留。

## Evidence 所有权

向量查询的 `user_id` 过滤是第一层边界。检索结果返回后，Evidence 服务会收集全部合法 `file_id` 并一次批量查询 `FileRecord`，随后验证：

- metadata user_id 存在时必须是当前用户；
- FileRecord 必须存在且属于当前用户；
- 分类和文件名只信任数据库记录；
- 缺失、非法、已删除、跨用户或非项目/简历来源的 chunk 会被丢弃。

UserProfile 和 TargetJob 使用当前用户条件直接查询。JD 只作为岗位要求，不作为用户能力证据。管理员执行普通 Agent 流程时同样不能绕过业务资料所有权。

## 输出关闭失败

Evaluation 的评价文本和优化回答、Resume 的全部正式描述字段在写库前执行确定性安全校验。模型首次返回不安全结果时最多重试一次；第二次仍不安全则返回受控错误，不保存当前结果，也不覆盖已有评价或简历版本。内部重试沿用同一次业务用量预留，不重复计费。

AgentRun 只记录 Agent、Prompt 版本、状态、耗时和脱敏错误类型，不记录 Prompt、回答、简历、JD、攻击原文或其他用户资源明细。

## 已知局限

当前守卫用于纵深防御，不能替代模型供应商安全能力和持续红队测试。Base64、同形异义字符、复杂语义改写及跨多个字段拼接的间接注入仍需继续扩充评估。
