# 检索候选与排序

## 处理链路

面试证据检索按以下顺序执行：

1. Chroma 使用当前 `user_id` 过滤并返回有上限的候选池。
2. 校验候选 metadata 的 `user_id` 和 `file_id` 基础格式。
3. Evidence 服务批量查询 `FileRecord`，校验文件存在、归属和分类。
4. 删除超过 `EVIDENCE_MAX_DISTANCE` 的候选，并应用调用上下文的分类过滤。
5. 删除完全重复内容，对同文件相邻近重复片段施加多样性惩罚。
6. 使用确定性综合分排序，最后截取调用方要求的 `top_k`。
7. 只从最终合法结果生成 `evidence_source_ids`。

普通知识库检索同样使用候选池、距离过滤、去重和重排；Evidence 在此基础上增加数据库所有权校验。管理员执行普通面试时不绕过该边界。

## 候选池

`top_k` 始终表示最终返回数量。内部候选数按以下规则计算：

```text
candidate_k = min(RETRIEVAL_MAX_CANDIDATES,
                  max(top_k, top_k * RETRIEVAL_CANDIDATE_MULTIPLIER))
```

默认配置为：

- `RETRIEVAL_CANDIDATE_MULTIPLIER=3`
- `RETRIEVAL_MAX_CANDIDATES=20`

配置由 Pydantic 校验。`top_k` 不能超过最大候选数，候选不足时返回实际数量，不会为补足数量放行超过距离阈值的结果。

## 排序信号

综合分由 70% 语义分和 30% 词项分组成。平方 L2 距离越小越相关，语义分在现有距离阈值内归一化。词项分只用于纠正距离接近的候选，包含：

- chunk 对唯一查询词的覆盖率；
- 规范化后的完整查询短语命中；
- 数据库可信文件名对查询词的覆盖率。

文本使用 Unicode NFKC 和不区分大小写的规范化。英文技术词保持整体，中文使用连续文本和二元片段，不依赖外部分词模型。词项集合去重，因此长文本或重复堆砌同一关键词不会天然获得更高分。

文件名信号只能由调用方提供数据库已验证的文件名，不能信任 Chroma metadata 中的文件名。分类信号只做明确调用上下文的过滤，不无条件提升某一分类。

## 去重与稳定性

完全相同的规范化内容只保留综合分更高且稳定排序靠前的候选。同一文件、相邻 chunk 且词项 Jaccard 相似度达到 0.75 时，后续候选减去 0.12 的多样性分；不同位置或内容独立的同文件 chunk 仍可同时返回。

相同综合分时依次使用：

1. 更小的向量距离；
2. `source_id`；
3. 规范化内容。

排序不使用随机数、时间或无序集合迭代顺序。

## 方案比较

在原始 8 个固定检索 case 上离线比较：

| 方案 | Recall@1 | Recall@3 | Recall@5 | MRR |
| --- | ---: | ---: | ---: | ---: |
| 纯向量距离 | 79.17% | 87.50% | 100% | 90.63% |
| 距离 + 词项覆盖 | 91.67% | 100% | 100% | 100% |
| 距离 + 词项覆盖 + 去重/多样性 | 91.67% | 100% | 100% | 100% |

最终选择第三种方案。它修复第 4 位相关来源无法进入最终前三的问题，同时对完全重复和相邻近重复结果提供约束；原有正确 case 未退化。

## 局限

- Mock 候选距离和顺序不代表真实 BGE 与生产 Chroma 的质量。
- 轻量词项分析不等价于中文语义分词，也不能替代 Cross Encoder。
- 70/30 权重只在固定离线集上验证，生产数据分布变化后需要独立校准。
- 当前去重针对完全重复和同文件相邻近重复，不处理跨文件语义改写型重复。

## 真实 BGE 校准结果

隔离的 35 query / 48 chunk 合成集显示，Mock 的 100% Recall@3 不能外推到真实向量：纯距离 Recall@3 为 66.15%，当前完整重排为 69.79%；去重/多样性提升 3 个 case，未检测到退化，但当前 `0.8` 阈值 false reject rate 为 37.5%，并有 5 个 case 的部分相关来源未进入候选池。

本阶段没有修改阈值、候选池或排序权重。阈值放宽到 0.9 会同时增加明显 false accept，候选倍数 4 也只减少 1 个截断 case，因此需要下一阶段独立分析，不能直接根据单一指标调参。完整方法与数据参见 [真实 Embedding 检索校准](RETRIEVAL_CALIBRATION.md)。

## 排序后的证据接受

当前 70/30 重排与 0.12 多样性惩罚保持不变；Agent 调用方在排序后增加独立的确定性充分性判断。`EVIDENCE_MAX_DISTANCE=0.8` 保留为高置信参考，平方 L2 `1.15` 是 Agent 证据硬拒绝边界。候选池上限由 20 调整为 40，但只在初次候选填满且边界开放时最多扩展一次，普通搜索展示接口不使用证据接受策略。

validation 支持选择“置信度 + 受控扩展”：Recall@3 84.26%、无答案 100%、FR 15.38%、FA 8.00%。final holdout 的 Recall@3 只有 70.37%、无答案 85.71%、FR 26.92%、FA 6.00%，说明方案改善拒答但多证据泛化仍不足。本阶段在 holdout 后不再修改参数。详见 [检索证据充分性](RETRIEVAL_CONFIDENCE.md)。
