# SPI面试Agent 本地演示流程

## 1. 演示目标

本演示用于展示 SPI面试Agent 的完整功能链路：

1. 系统状态自检；
2. 本地知识库上传与索引构建；
3. 基于 RAG 的自由问答；
4. 岗位 JD 分析；
5. 模拟面试与回答评价；
6. LangGraph Agent 自动路由；
7. 历史记录查看；
8. Agent 路由原因与执行轨迹查看。

项目重点展示：

* FastAPI + React 前后端分离能力；
* RAG 知识库问答能力；
* Tavily 联网搜索增强能力；
* LangGraph Agent 工作流能力；
* 面向 AI 应用开发实习求职场景的产品化设计能力。

---

## 2. 启动项目

### 2.1 启动后端

打开 PowerShell：

```powershell
cd D:\spir\NO1_agent\backend
.\.venv\Scripts\activate
uvicorn app.main:app --reload
```

后端启动成功后，访问：

```text
http://127.0.0.1:8000/docs
```

确认 Swagger 页面正常打开。

---

### 2.2 启动前端

另开一个 PowerShell：

```powershell
cd D:\spir\NO1_agent\frontend
npm run dev
```

前端启动成功后，访问：

```text
http://localhost:5173
```

## 3. 演示步骤

## 3.1 系统状态自检

进入页面：

```text
系统状态
```

重点展示：

1. 后端状态为 ok；
2. DeepSeek API Key 已配置；
3. Tavily API Key 已配置；
4. 数据库记录数量正常；
5. 知识库状态可读取；
6. 向量片段数正常。

演示说明：

```text
这个页面用于快速检查系统是否具备运行条件，包括后端服务、API Key、数据库和知识库索引状态。它可以避免演示时不知道问题出在哪里。
```

---

## 3.2 知识库管理

进入页面：

```text
知识库管理
```

演示内容：

1. 上传 Markdown / TXT / PDF 文件；
2. 查看已上传文件列表；
3. 点击“重建知识库索引”；
4. 查看知识库状态；
5. 确认向量片段数变化。

推荐演示说法：

```text
这一部分是 RAG 的数据入口。用户上传项目资料、技术笔记或简历内容后，系统会解析文档，切分文本，并写入 ChromaDB 向量库。后续自由问答、岗位分析、模拟面试和 Agent 都可以使用这些本地知识库内容。
```

注意：

```text
上传文件后必须重建知识库索引，否则新文件不会进入向量检索。
```

---

## 3.3 RAG 自由问答

进入页面：

```text
自由问答
```

推荐测试问题：

```text
根据我的本地知识库，介绍这个 RAG 项目的核心流程。
```

重点展示：

1. 系统基于本地知识库回答；
2. 回答中不会编造用户没有上传过的经历；
3. 页面显示本地知识库引用来源；
4. 问答记录会保存到历史记录。

演示说法：

```text
自由问答模块的核心是 RAG。后端先用用户问题检索 ChromaDB 中的相关片段，再把检索内容和问题一起发送给 DeepSeek 生成回答。这样可以让模型回答更贴近用户自己的项目资料，而不是纯靠模型泛泛而谈。
```

---

## 3.4 岗位 JD 分析

进入页面：

```text
岗位分析
```

推荐测试 JD：

```text
岗位名称：AI 应用开发实习生

岗位职责：
1. 参与 AI 应用后端接口开发；
2. 使用 FastAPI 或 Flask 构建 API 服务；
3. 参与 RAG 知识库问答系统开发；
4. 对接大模型 API，完成 Prompt 调试；
5. 参与前端页面联调和项目部署。

岗位要求：
1. 熟悉 Python；
2. 了解 FastAPI、RESTful API；
3. 了解向量数据库、Embedding、RAG；
4. 了解 React 前端开发；
5. 有 LangChain、LangGraph 或 Agent 项目经验优先。
```

演示步骤：

1. 粘贴 JD；
2. 先不启用联网搜索，测试本地分析；
3. 再启用 Tavily 联网搜索；
4. 对比联网增强后的分析结果；
5. 查看联网搜索来源。

演示说法：

```text
岗位分析模块会把岗位 JD 与用户本地知识库进行对比，分析匹配点、短板和准备建议。启用 Tavily 后，系统还会补充当前岗位市场信息，但它不会用联网内容证明用户具备某项能力，用户能力仍然只依据本地知识库。
```

## 3.5 模拟面试

进入页面：

```text
模拟面试
```

推荐演示流程：

1. 生成一个面试问题；
2. 输入用户回答；
3. 提交评价；
4. 查看评分、问题分析、改进建议和参考回答。

推荐回答样例：

```text
我这个项目主要是一个面向 AI 应用开发实习的 RAG 面试训练系统。后端使用 FastAPI 提供接口，前端使用 React 构建页面，知识库部分支持上传 Markdown、TXT 和 PDF 文件。系统会解析文档并切分文本，然后通过 embedding 模型写入 ChromaDB。用户提问时，系统会先检索相关知识片段，再调用 DeepSeek 生成回答。后续我还加入了 Tavily 联网搜索和 LangGraph Agent，用于根据问题自动选择本地知识库、联网搜索或混合检索。
```

演示说法：

```text
模拟面试模块用于训练用户把项目讲清楚。系统不仅给分，还会指出回答中的问题，例如是否偏离问题、是否缺少技术细节、是否有编造风险，以及如何改进表达结构。
```

## 3.6 LangGraph Agent

进入页面：

```text
LangGraph Agent
```

推荐测试 1：local

```text
根据我的本地知识库，介绍这个 RAG 项目的核心流程。
```

预期：

```text
实际路由：local
本地知识库：已使用
联网搜索：未使用
```

推荐测试 2：web

```text
现在 AI 应用开发实习岗位有哪些常见要求？
```

预期：

```text
实际路由：web 或 hybrid
联网搜索：已使用
```

推荐测试 3：hybrid

```text
结合当前 AI 应用开发实习岗位要求，分析我的 RAG 项目怎么准备面试。
```

预期：

```text
实际路由：hybrid
本地知识库：已使用
联网搜索：已使用
```

重点展示：

1. Agent 执行流程说明；
2. LLM Router 路由判断；
3. route_reason 路由原因；
4. execution_steps 执行轨迹；
5. 本地知识库引用来源；
6. 联网搜索来源。

演示说法：

```text
这个模块是项目的 Agent 化部分。我没有只做普通问答，而是用 LangGraph 把流程拆成多个节点：Router、Local Retrieval、Web Search 和 Answer Generation。auto 模式下，系统会先让 LLM Router 判断问题应该走 local、web 还是 hybrid，然后再执行对应的工具链路。
```

## 4. 演示重点总结

本项目可以按下面四个层次介绍：

### 4.1 基础工程层

```text
FastAPI + React + SQLite，实现前后端分离、接口调用、数据持久化和页面交互。
```

### 4.2 RAG 能力层

```text
支持文档上传、文本解析、切分、embedding、ChromaDB 检索和基于知识库的回答生成。
```

### 4.3 联网增强层

```text
通过 Tavily 获取当前岗位市场和技术趋势信息，用于补充岗位分析和 Agent 回答。
```

### 4.4 Agent 工作流层

```text
使用 LangGraph 构建 Router → Local Retrieval → Web Search → Answer Generation 的工作流，支持自动路由和执行轨迹记录。
```

## 5. 演示注意事项

1. 演示前确认后端和前端都已启动；
2. 演示前确认 `.env` 中 DeepSeek 和 Tavily Key 已配置；
3. 演示前确认知识库已经重建索引；
4. 首次加载 embedding 模型可能较慢；
5. Tavily 搜索失败时，优先检查网络和 API Key；
6. 不要展示真实 API Key；
7. 不要把 `backend/.env`、`backend/data/`、`backend/.venv/`、`frontend/node_modules/` 提交到 Git。
