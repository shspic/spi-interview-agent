# AURORA 产品视觉与界面重构规范

版本：V1.0
产品：AURORA
英文副标题：AI Interview Intelligence
中文标语：让潜力被看见，让成长有迹可循

## 0. 设计范围与约束

本规范面向现有 React + Vite 多页面 Web 应用，覆盖认证、面试、知识库、历史、用量、设置和管理后台。它是视觉与交互重构方案，不调整现有业务字段、接口、权限边界和既有路由，也不要求把页面集中到单一 `App.tsx`。

当前项目中的真实认证字段是用户名、密码、确认密码和邀请码；注册页必须沿用这些字段，不照搬参考提示词中的姓名、邮箱或第三方 OAuth。密码重置新增页面的具体账号标识字段、状态枚举和 URL 尚未在现有前端中出现，设计稿只定义结构和视觉状态，实施时必须映射到最终接口，不预设邮箱、手机号或任何第三方登录能力。

全站采用“双舱模式”：

| 模式 | 适用页面 | 装饰强度 | 核心目标 |
|---|---|---:|---|
| 深空接驳舱 | 登录、注册、密码重置申请、强制修改临时密码 | L3 高沉浸 | 建立品牌记忆与安全、可信的入口体验 |
| 任务舰桥 | 面试、结果、知识库、历史、用量、设置、管理后台 | L1–L2 低装饰 | 保证长文本、表格、评分和连续操作的可读性 |

“深空 HUD”只是一层秩序感，不是满屏装饰。业务页面不使用大面积星云视频、扫描线或高亮发光文字。

## 一、整体品牌设计方向

### 1. 品牌定位

AURORA 不是替用户“生成标准答案”的工具，而是一套基于真实资料进行练习、评价、证据校验和复盘的面试智能系统。品牌气质应同时传达：

- 精密：像深空任务终端，信息有坐标、有状态、有证据。
- 克制：不追求游戏化炫技，关键业务信息永远高于视觉装饰。
- 可信：资料冲突、无依据内容和系统状态必须被明确呈现。
- 成长：评分不是终点，改进任务与再次练习形成可追踪闭环。

品牌叙事为“从暗处识别信号”。AURORA 的冷青色表示被识别的潜力与有效证据，琥珀色表示下一步行动与需要关注的变化。

### 2. 视觉关键词

深空舰桥、舷窗、信号扫描、轨道、低照度玻璃、金属舱体、冷青辉光、琥珀导航点、证据坐标、安静而精密。

禁止方向：普通蓝白 SaaS、高饱和紫色渐变、卡通插画、过度霓虹、密集网格、纯装饰雷达图、频闪与持续晃动。

### 3. 色彩体系

#### 3.1 品牌基础色

| Token | 色值 | 用途 |
|---|---|---|
| `void` | `#05080D` | 认证页最深背景、遮罩 |
| `abyss` | `#0A1520` | 应用全局背景 |
| `hull` | `#0F2233` | 侧栏、较强容器 |
| `deck` | `#0C1A24` | 工作区主表面 |
| `panel` | `#112632` | 卡片、抽屉、弹窗 |
| `cyan-glow` | `#4DD8E6` | 品牌识别、焦点、选中状态 |
| `teal-deep` | `#1B6B7A` | 低刺激主按钮、进度底色 |
| `amber-warm` | `#FFB765` | 核心行动、提醒、成长节点 |
| `neon-green` | `#7CFF9E` | 成功、在线、已完成 |
| `nebula-orange` | `#FF7A3D` | 高强度警示的辅助强调，不作大面积填充 |

#### 3.2 文本与语义色

| Token | 色值 | 用途 |
|---|---|---|
| `text-primary` | `#EAF8FA` | 标题、正文主信息 |
| `text-secondary` | `#AFC5CC` | 描述、表格次级信息 |
| `text-muted` | `#748C95` | 时间、辅助说明、HUD 标签 |
| `info` | `#69C8FF` | 信息提示 |
| `success` | `#7CFF9E` | 成功、在线、完成 |
| `warning` | `#FFB765` | 无依据内容、额度预警、待处理 |
| `danger` | `#FF6B78` | 资料冲突、失败、删除 |

规则：

- 正文不直接使用低透明度青色；主文本必须达到 WCAG AA。
- 青色用于“当前、可交互、已识别”，琥珀色用于“下一步、待关注”，红色只用于“冲突、失败、不可逆”。
- 亮色按钮上的文字使用 `#071013`，避免白字在高亮底色上对比不足。
- 工作区背景以近黑蓝为主，不使用大面积纯黑或纯白。

### 4. 字体体系

- 中文正文：`Noto Sans SC / PingFang SC / Microsoft YaHei / system-ui`。
- 英文与数字：`Inter`。
- HUD、状态码、时间、任务 ID：`JetBrains Mono` 或系统等宽字体。
- 业务正文禁止使用等宽字体；中文长文本行高为 1.7–1.8，理想行宽 56–72 个中文字符。

建议字阶：

| 层级 | 桌面 | 移动 | 用途 |
|---|---:|---:|---|
| Display | 40/48，600 | 32/40，600 | 认证页主标题 |
| H1 | 28/38，650 | 24/34，650 | 页面标题 |
| H2 | 22/32，650 | 20/30，650 | 大区块标题 |
| H3 | 18/28，600 | 18/28，600 | 卡片标题 |
| Body | 15/26，400 | 16/28，400 | 业务正文、输入内容 |
| Small | 13/20，400 | 13/20，400 | 辅助说明 |
| HUD | 11/16，500 | 11/16，500 | 英文标识、状态码，字距 0.08em |

### 5. 图标体系

- 使用统一线性图标，默认 20px、1.75px 描边；重要按钮 18px，导航 20px，空状态 32–40px。
- 图标只辅助中文标签，不用 emoji 代替。
- 推荐语义：轨道/品牌、仪表/面试、资料库/知识库、时钟/历史、计量/用量、齿轮/设置、盾牌/管理、安全钥匙/密码。
- 当前工程已有 `public/icons.svg`，实施时优先复用；如需引入新图标库，必须作为独立依赖决策，不在视觉重构中静默增加。

### 6. 动效原则

- 页面与卡片进入：160–240ms，透明度 0→1，位移不超过 8px。
- 折叠展开：180–220ms；只动画高度、透明度或箭头旋转。
- 按钮按下：缩放不低于 0.98，持续 80–120ms。
- 进度更新：300–500ms 平滑过渡，不使用无限循环跑马灯。
- 认证页允许 Logo 30 秒缓慢旋转、在线点 2 秒轻呼吸；工作区不保留持续动画。
- 视频默认静音自动播放；用户启用“减少动态效果”或设备性能不足时，停止非必要动画并保留静态首帧/深色兜底。
- 禁止频闪、视差晃动、持续扫描光束、影响输入焦点的动画。

### 7. 背景和材质原则

#### L3：认证入口

- 舷窗视频 + 深色渐变遮罩 + 金属内阴影 + 极淡扫描线。
- 表单玻璃面板透明度 82%–90%，必须有实色兜底。
- HUD 网格只在空白背景出现，强度不超过 3%。

#### L2：面试准备与进行中

- 使用静态径向青色光晕和极淡网格，不使用视频。
- 问题卡、输入区为高不透明表面，视觉焦点只保留在当前问题和主操作。

#### L1：结果、历史、设置

- 深色平面为主，玻璃只用于顶部总览或重要状态卡。
- 不使用扫描线；阴影接近不可见，以边框和表面层级分区。

#### L0：管理后台和密集表格

- 近乎实色表面，减少发光、渐变和透明叠层。
- 表头、筛选区、危险操作区通过明度和语义边框区分。

## 二、全站设计系统

### 1. Design Tokens

#### 1.1 间距

采用 4px 基线：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。

- 图标与文字：8px。
- 同一表单字段内部：8px。
- 相关字段组：16px。
- 卡片内边距：桌面 20–24px，移动 16px。
- 页面区块间距：桌面 32px，移动 24px。
- 桌面内容区左右安全距：32px；移动：16px。

### 2. 圆角、边框与阴影

| 项目 | 规范 |
|---|---|
| 小控件 | 6px |
| 输入框、按钮、标签组 | 8px |
| 普通卡片 | 12px |
| 总览卡、弹窗、抽屉 | 16px |
| 认证舷窗 | 24px |
| 胶囊状态 | 999px |
| 普通边框 | 1px `rgba(77,216,230,0.16)` |
| 强调边框 | 1px `rgba(77,216,230,0.38)` |
| 分隔线 | 1px `rgba(175,197,204,0.12)` |
| 焦点环 | 2px `rgba(77,216,230,0.72)` + 2px 外间隔 |

阴影：

- `shadow-soft`：`0 10px 30px rgba(0,0,0,0.18)`。
- `shadow-float`：`0 20px 60px rgba(0,0,0,0.32)`。
- `glow-cyan`：`0 0 24px rgba(77,216,230,0.12)`，只用于当前焦点。
- `glow-amber`：`0 0 20px rgba(255,183,101,0.12)`，只用于主行动。

工作区卡片不得同时使用强阴影、强发光和高亮边框。

### 3. 玻璃透明度

| 场景 | 背景不透明度 | 模糊 |
|---|---:|---:|
| 认证表单 | 0.82–0.90 | 18–24px |
| 顶部总览 | 0.90–0.94 | 12–16px |
| 普通业务卡 | 0.94–0.98 | 0–8px |
| 表格、长文本、输入区 | 0.98–1.00 | 0 |
| 弹窗 | 0.96–1.00 | 16px |

任何玻璃表面都必须在不支持 `backdrop-filter` 时保持可读。

### 4. 状态色

- 信息：蓝青色左边框，深蓝底。
- 成功：绿色图标/文字，暗绿底；禁止整卡荧光绿。
- 警告：琥珀色边框和标题，暗棕底。
- 危险：红色边框和标题，暗红底。
- 中性：灰青文字和边框。
- 当前进行：青色边框 + 细进度线。

状态不可只靠颜色表达，必须同时提供图标、文本或状态标签。

### 5. 按钮

| 类型 | 视觉 | 用途 |
|---|---|---|
| Primary | 深青填充、青色边框、浅色文字 | 工作区主要操作 |
| Brand CTA | 琥珀填充、深色文字 | 认证提交、开始新一轮等唯一高优行动 |
| Secondary | 透明/深色表面、普通边框 | 次要操作 |
| Ghost | 无填充，hover 出现表面 | 导航、折叠、复制 |
| Danger | 暗红填充或红色描边 | 删除、取消、不可逆操作 |

按钮高度：桌面 40px，主要按钮 44px；移动端全部至少 48px。图标按钮命中区至少 44×44px。加载时保留原按钮宽度，显示旋转图标和明确文字。

### 6. 输入框

- 高度：桌面 44px，移动 48px；移动文字不小于 16px。
- 背景：`#091720`；输入文字为 `text-primary`。
- 默认边框低对比，focus 使用青色边框和焦点环。
- 错误状态显示红色边框、字段下方错误文本和 `aria-describedby`。
- 帮助文本与错误文本位置固定，避免页面跳动。
- 长回答文本区最小高度：桌面 280px，移动 220px；允许垂直调整但不允许横向调整。
- 自动填充必须保持深色背景和可见光标。

### 7. 卡片、标签和提示框

- `SurfaceCard`：普通内容卡，12px 圆角。
- `MetricCard`：单指标卡，数字为第一层级，不加复杂仪表。
- `ActionCard`：带单一明确 CTA，允许琥珀色顶边。
- `RiskCard`：冲突/无依据专用，风险标题固定在最上方。
- `StatusTag`：高度 24px，圆角 999px；文本不超过 8 个汉字。
- `HUDTag`：等宽字体、英文大写，用于 `SYS_ONLINE`、任务码、状态码；不承担核心业务解释。
- `InlineNotice`：页面内反馈，不遮挡操作。
- `Toast`：只用于复制成功、保存成功等短反馈，4 秒内消失；错误不得只用 Toast。

### 8. 弹窗与抽屉

- 桌面弹窗宽 480–640px，移动改为底部抽屉或全屏对话层。
- 删除、取消面试、清理数据、审批密码重置均使用自定义确认层，不使用浏览器原生弹窗。
- 标题先说明后果，正文说明影响范围，主操作使用明确动词，取消按钮在前、危险按钮在后。
- 初始焦点落在标题或安全操作，关闭后焦点返回触发按钮。

### 9. 表格

- 表头高度 44px，行高不低于 48px。
- 数字右对齐，文本左对齐；状态和操作列保持稳定宽度。
- 表头使用高不透明表面，不使用玻璃模糊。
- Hover 只增加 3%–5% 明度。
- 桌面允许固定表头；超过 8 列时使用列显示控制或横向滚动。
- 移动端优先转换为键值卡片；确需保留表格时，容器横向滚动并保持操作按钮可见。

### 10. 空状态、Loading 与任务进度

空状态包含：线性图标、结论、原因/下一步、一个主要操作。禁止只写“暂无数据”。

Loading 分三类：

- 首屏：结构化骨架屏，保持最终布局尺寸。
- 局部操作：按钮内加载，不锁定整个页面。
- 后台任务：常驻任务卡，显示“排队中 / 处理中 / 已完成 / 失败 / 已取消”等接口实际返回状态。

进度：

- 可计算任务显示百分比和已处理数量。
- 不可计算任务显示阶段名称，不伪造百分比。
- 失败态保留错误摘要、重试和查看详情入口。
- 完成后任务卡收起为一行状态，不自动将用户从当前输入区跳走。

## 三、页面结构方案

### 1. 全站框架

桌面：

```text
┌──────── 248px 导航舱 ────────┬──────────────────────────────┐
│ AURORA                       │ 页面标题 / 上下文 / 全局状态    │
│ AI Interview Intelligence    ├──────────────────────────────┤
│ 主导航                        │ 页面内容，最大宽 1440px         │
│                              │                              │
│ 用户 / 用量 / 设置 / 退出      │                              │
└──────────────────────────────┴──────────────────────────────┘
```

移动：

```text
┌ 顶栏：菜单 / AURORA / 任务状态 ┐
├ 页面标题与关键操作              ┤
├ 单列内容，自然滚动              ┤
└ 必要时使用安全区底部操作栏       ┘
```

导航采用中文业务名称；`AURORA`、`AI Interview Intelligence`、少量状态码保留英文。移动抽屉关闭后不得遮挡或锁住页面滚动。

### 2. 登录

桌面 52/48 双栏：左侧舷窗视频与品牌叙事，右侧登录终端。右栏字段严格为用户名和密码；“忘记密码”在密码标签右侧。主按钮“登录 AURORA”，下方为“没有账号？使用邀请码注册”。不出现 Google、GitHub 或其他 OAuth。

移动端先显示 180–220px 舷窗和品牌，再显示表单；视频只作为顶部品牌模块，不占首屏大半高度。错误提示紧贴表单，服务不可用提示与凭据错误分开呈现。

### 3. 注册

沿用现有字段：用户名、密码、确认密码、邀请码。桌面表单为单列，避免把无关字段塞入双列；邀请码作为独立“访问凭证”区。密码规则在输入前可见，校验失败后逐字段呈现。

注册成功后进入现有登录/会话流程，不展示“等待邮箱验证”等不存在状态。

### 4. 密码重置申请

- 与登录页共用 `AuthShell`，沉浸强度降至 L2。
- 标题“申请重置密码”，正文解释申请将进入管理员审批。
- 账号标识输入字段名称完全以最终接口为准，不预设邮箱或手机号。
- 提交后统一显示中性成功信息，避免泄露账号是否存在。
- 提供返回登录入口；重复提交、限流、服务失败使用独立状态。

### 5. 强制修改临时密码

- 取消舷窗视频，以安全终端为主，避免用户误以为可以跳过。
- 顶部明确显示“需要更新密码”与原因，品牌信息退到次级。
- 表单字段按最终接口呈现；新密码与确认密码必须有独立错误。
- 主按钮“更新密码并继续”，页面不提供进入业务区的绕过入口。
- 成功后给出一次明确确认，再进入现有授权流程。

### 6. 面试准备

桌面主区 8/4：

- 左侧：资料就绪度、面试模式、会话标题、目标岗位、项目文件、创建并开始。
- 右侧：当前目标岗位摘要、资料缺口与最近草稿。
- 三种面试模式使用选择卡，选中态为青色边框，不使用大面积亮色底。
- 资料不足用琥珀提示，不阻止允许继续的模式。

移动按“就绪状态 → 模式 → 岗位 → 项目文件 → 开始”排序；项目文件使用可换行选择项，主按钮位于内容底部，不悬浮遮挡字段。

### 7. 正在面试

- 顶部紧凑展示主问题进度、当前题、追问次数和模式。
- 当前问题卡占主视觉；状态与题号是次级，题目正文是第一层级。
- 回答区与题目同卡或紧邻，减少视线跳转。
- “证据有限”固定出现在题目与输入区之间。
- 提交后显示后台评价阶段，不把回答文本清空；评价完成后展示本题反馈和“继续下一题”。
- 取消会话为危险次级操作，放在更多菜单或卡片右上角，不与提交按钮并列抢夺注意力。

移动端保留题目、回答和提交的单一任务流。进度信息压缩为两行，不使用四张纵向指标卡。

### 8. 面试结果

采用“总览 → 风险 → 问题诊断 → 行动”的顺序，详见第四部分。默认不展开全部问题。

### 9. 改进任务

- 顶部显示整体诊断、下一轮策略、任务完成率。
- 任务按高/中/低优先级和类别筛选，但默认仍按现有返回顺序。
- 每项包含状态、标题、说明、来源问题和完成标准。
- 完成操作使用复选框；保存中保持原位置，失败后恢复并显示行内错误。
- 移动端隐藏非必要元数据，来源问题可折叠。

### 10. 再次练习

- 首屏先回答“为什么再练”：上一轮总分、已完成任务、仍需加强维度。
- 展示本轮继承的训练策略和数据范围，明确“训练策略不是事实证据”。
- 主操作“确认并开始新一轮”；成绩对比在练习完成后展示。
- 对比使用精确的条形与增减数值，不用雷达图。

### 11. 知识库

结构顺序：

1. 资料状态总览：文件总数、已索引、失败、向量片段。
2. 上传区：文件、分类、大小限制和上传进度。
3. 搜索区：语义搜索说明和结果。
4. 文件列表：文件名、类型、分类、状态、时间、操作。
5. 后台索引任务：放在全局任务中心与本页状态区，不重复大块展示。

桌面上传区为横向工具栏；移动为纵向表单。失败文件行使用红色状态和“查看原因/重试”入口；删除为行内危险操作。

### 12. 历史记录

- 顶部保留现有历史类型切换，但采用可滚动分段标签。
- 桌面为“记录列表 40% + 详情 60%”；选中后原位更新详情。
- 面试训练记录优先显示标题、状态、模式、总分、时间和改进任务完成度。
- 移动端先列表，点击后进入同页全屏详情层或纵向详情，不并排压缩。
- 空筛选结果提供“清除筛选”，无任何记录时提供“开始面试”。

### 13. 用量

- 顶部展示当前用量周期和刷新时间。
- 核心额度卡显示已用/上限/剩余；接近 80% 使用琥珀，耗尽使用红色。
- 细分调用量使用两列指标卡，数字优先，说明次级。
- 不用环形图堆叠小数字；进度条必须同时提供文本。

### 14. 设置

- 分为“账户安全 / 会话与设备 / 数据与隐私”。
- 修改密码为普通安全卡；退出所有设备为强调次级操作。
- 数据清理与删除账号放入独立危险区，默认折叠预计影响。
- 危险操作使用多步确认层，不让红色覆盖整页。
- 移动端所有表单单列，危险确认文本和当前密码字段保持在同一上下文。

### 15. 管理后台

- 装饰强度 L0；顶部为管理员身份、日期范围和刷新。
- 一级标签保留现有任务、概览、用户、用量、运行记录、邀请码、清理、审计，并新增密码重置审批区域；新增入口可以是一级标签，也可以在用户管理内作为二级区，最终取决于现有权限和接口组织。
- 概览采用 4 张关键指标卡 + 两列运行摘要。
- 表格统一使用固定表头、筛选工具栏、分页和行内状态。
- 审批区列表只展示接口实际返回的账号标识、申请时间、状态和可用风险信息，不虚构邮箱或手机号。
- 审批/拒绝在详情抽屉中完成；临时密码如由后端返回，不在列表中长期明文展示。
- 移动端指标改为 2 列或 1 列；表格改为摘要卡 + 详情抽屉，敏感操作保持二次确认。

### 1. 桌面布局

应用外壳保持左侧主导航。结果页内容最大宽 1440px，内部采用 12 列网格：

```text
├────────────────────── 五维评分 12列 ──────────────────────┤
│ 技术准确 78 │ 资料一致 92 │ 回答深度 70 │ 表达结构 86 │ 匹配 81 │
├───────────────────────────────┬───────────────────────────┤
│ 问题区 8列                    │ 情境侧栏 4列，sticky        │
│ [全部][需改进][冲突][无依据]    │ 下一步行动                  │
│ Q1 标题 / 82 / 正常       ▾   │ 改进任务进度                │

│ │ 当前标签内容              │ │                           │
│ └─────────────────────────┘ │                           │

└───────────────────────────────┴───────────────────────────┘
```

#### 顶部总览

- 总分使用 96–120px 的数字区，不使用发光圆环；数字、满分说明和结果等级构成清晰层级。
- 会话总结默认显示 3 行，可展开；标题、模式、岗位和完成时间在同一区域。
- 右侧显示“资料冲突 X 项 / 无依据 X 项”，有风险时始终可见。
- 主要操作顺序：查看改进任务、再次练习、生成简历描述；成绩对比为次级。

#### 五维评分

- 使用五个等宽条形指标，不用雷达图。
- 每项包含中文名称、分数、水平条和相对状态。
- 低于预设阈值的维度用琥珀色，不直接用红色；红色只用于证据风险。
- 在 1024–1180px 下改为 3+2 布局。

#### 问题列表

- 默认全部折叠；若存在资料冲突，默认展开第一道冲突题；否则展开最低分题。
- 列表头提供前端本地筛选：全部、需改进、资料冲突、无依据内容。筛选基于现有结果数据，不新增接口。
- 折叠行显示：题号/追问、问题一行摘要、单题分、风险标签和展开按钮。
- 同时只展开一道题；用户可选择“保持多项展开”，但不作为默认行为。

#### 展开后的问题

风险条固定放在标签内容之前：

- “资料冲突”使用红色边框和图标，逐条展示冲突描述。
- “无依据内容”使用琥珀色边框，逐条展示未经资料支持的陈述。
- 两者同时存在时分成两个独立区块，不混成一段红色长文。

详情使用四个局部标签：

1. **诊断**：得分、做得好的地方、存在的问题、修改理由。
2. **原回答**：保留完整原文；默认先显示 8 行，可继续展开。
3. **优化回答**：完整展示优化文本，提供复制；宽屏可切换“与原回答对照”。
4. **改进任务**：只展示来源于本题的任务及完成标准。

标签切换只改变当前题的局部内容，不改变 URL，不请求新接口。

#### 原回答与优化回答

- 单独查看时文本宽度不超过 72ch。
- 对照模式在内容宽度 ≥1100px 时左右两栏；较窄桌面和移动端上下排列。
- 原回答使用中性表面，优化回答使用非常轻的青色顶边，避免“优化”被误解为唯一正确答案。
- 复制成功使用短 Toast；复制失败保留可选中文本和行内提示。

#### 改进任务

- 侧栏显示总体完成率和前三项高优先级任务。
- 问题展开区只显示与该题关联的任务。
- “查看全部改进任务”切换到现有改进任务区，不新增路由。

#### 最近会话

不再作为独立大卡长期占用右侧：

- 只显示 3 条与当前任务相关的最近会话，包含标题、状态、分数和时间。
- 当前会话置顶并明确标记。
- “查看全部”进入现有历史记录页或现有会话列表能力。
- 当用户滚动到问题区时，侧栏首先保留“下一步行动”和任务进度，最近会话位于下方并可折叠。

### 2. 移动布局

```text
┌ 总分 + 会话标题 ─────────────┐
│ 84 / 100  总结（2行，可展开） │
│ 冲突 1 · 无依据 2             │
```

- 总览改为单卡，分数在左、标题与风险在右；小于 360px 时改为上下布局。

## 五、交付与实施规范

### 1. 核心页面高保真视觉描述

#### 认证入口

背景近黑，舷窗视频位于左侧金属框内，星云色彩经过深蓝遮罩压低饱和度。AURORA 标识和标语位于舷窗下方，不叠在高对比视频区域。右侧表单像嵌入舱壁的安全终端：面板轮廓清晰、发光克制、输入区近乎实色。琥珀按钮是唯一高亮行动。

#### 正在面试

像安静的任务执行台。背景只保留静态青色光晕，题目卡使用高不透明深蓝表面。进度在顶部以细线和数字表达，当前问题大而清晰。回答框无网格和扫描线，光标、字数和提交状态明确。评价等待阶段在原位置显示，不让界面跳动。

#### 面试结果

像任务复盘台。总分与五维评分形成第一屏，证据风险紧邻总览。下方问题列表以折叠行构成稳定节奏，展开后通过局部标签控制长文本。青色表示可行动与有效信息，红/琥珀只标记证据风险。

#### 管理后台

像低装饰运行控制台。背景、表格和筛选区以明度区分，不使用星云或扫描线。状态标签小而清晰，危险操作藏于行尾或详情抽屉。管理员可以长时间阅读表格而不疲劳。

### 2. 响应式规则

| 宽度 | 规则 |
|---|---|
| 320–767px | 单列；导航抽屉；输入 16px；操作命中区 ≥44px；无整页横向滚动 |
| 768–1023px | 单列或 8/4 简化布局；导航可收起；表格按内容选择卡片化或横向滚动 |
| 1024–1439px | 完整桌面壳；认证双栏；结果 8/4；内容边距 24–32px |
| ≥1440px | 内容最大宽 1440px；不无限拉长文本；侧栏和主区保持稳定比例 |

通用规则：

- 375px 宽度必须无横向溢出。
- 认证页桌面/移动只加载一份视频资源。
- 桌面侧栏固定宽度 248px；移动抽屉最大宽 86vw。
- 长文本容器使用 `overflow-wrap:anywhere`，代码或 ID 可水平滚动。
- 表单不通过隐藏两套 DOM 实现响应式，输入状态必须连续。

#### 面试

- 资料未准备、部分准备、已就绪。
- 会话草稿、启动中、进行中、回答保存中、评价中、可恢复、已完成、已取消。

#### 知识库、历史和用量

- 无文件、上传中、待索引、处理中、已索引、索引失败、搜索无结果。
- 历史加载中、无记录、筛选无结果、详情加载失败。
- 用量正常、接近上限、已耗尽、读取失败。

#### 管理后台

- 无权限、列表加载、空数据、筛选无结果、部分接口失败、审批确认、危险操作确认、操作完成/失败。

### 5. 前端执行规范

1. 先建立主题 Token 和基础组件，再改页面；不得逐页复制颜色值。
2. 保留现有 React + Vite 架构、页面路由、认证守卫、Cookie Session、CSRF 和权限判断。
3. 认证页只替换视觉壳和信息层级，字段与提交行为保持不变。
4. 结果页先拆出总览、五维评分、问题折叠和风险提示组件，再接入现有 `session` 与 `turn` 数据。
5. 任何本地筛选、折叠、标签切换都是表现层状态，不增加模拟接口。
6. 管理员密码重置审批只在真实接口和权限规则明确后接入；视觉稿不得先行虚构字段。
7. 所有交互支持键盘；焦点可见；折叠按钮使用正确的展开状态；弹窗具备焦点管理。
8. 深色主题正文、标签、输入和状态必须通过 WCAG AA 对比检查。
9. 尊重 `prefers-reduced-motion`；后台运行状态不使用闪烁表达。
10. 移动端验证 320、375、390、768px；桌面验证 1024、1280、1440、1920px。
11. 重点视觉回归：登录、注册、面试准备、正在面试、面试结果、知识库表格、设置危险区、管理审批区。
12. 性能目标：视频只在认证页加载；工作区不使用视频；毛玻璃层数量受控；长列表使用现有分页或增量呈现能力。

### 6. 验收标准

- AURORA 名称、副标题与中文标语在品牌入口准确出现。
- 认证页有深空舷窗与 HUD 气质，但不存在 OAuth 或虚构字段。
- 工作区不再呈现普通蓝白 SaaS，也没有大面积高饱和紫色。
- 结果首屏能同时看见总分、五维评分和证据风险。
- 问题默认折叠，展开后能快速切换原回答、评价、风险、优化回答和改进任务。
- 资料冲突与无依据内容颜色、图标和文案均有区别。
- 最近会话不再占据高价值主内容空间，移动端不保留右侧栏。
- 管理后台长表格清晰，危险操作与普通操作有明确层级。
- 375px 无横向溢出，移动输入字号不小于 16px。
- 无频闪、持续晃动或妨碍输入的动画。
- 没有改变现有字段、接口、既有路由、认证与权限边界。
